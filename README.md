# Bogey plugins

First-party extensions for [Bogey](https://github.com/0xethen/bogey). Each folder in `plugins/` is one plugin
(`manifest.ts`, `runtime.tsx`, and optionally `schema.sql`, `seed.sql` and `tests/`).

This repository is a Bogey _library_: `index.json` lists its plugins, which live in `plugins/<key>/`.
Install one into an instance of Bogey 2:

```sh
bogey plugins search
bogey plugins add <plugin>            # or <plugin>@<version>, or github:0xethen/bogeyx/<plugin>@<version>
```

That downloads the tagged release, shows the plugin's manifest and SQL, and asks before
anything is applied. Plugins are trusted code that runs with the app's privileges; read
what you install. See Bogey's `docs/plugins.md` and ADR 0012.

`index.json` lists every plugin here with its version and description. It is generated by
`node build-index.mjs` and checked in CI. `schema/library.schema.json` describes it (from `bogey plugins schema`), and
`$schema`-aware editors can use `schema/libraries.schema.json` for an instance's `bogey.libraries.json`.

To make your own library, copy this layout: plugins in `plugins/<key>/`, `build-index.mjs`, the release workflow, and tell
people to run `bogey plugins library add github:<you>/<repo>`.

## Developing here

Bogey loads plugins from `packages/plugins/installed/`. For development, `bogey plugins link` makes
that folder a symlink to this checkout's `plugins/` and fills `node_modules` here with links to the plugins
package's dependencies (and `@bogey/plugins` itself), so a plugin's imports (`@bogey/ui`, `react`,
...) resolve. It also writes a `tsconfig.json` (git-ignored) so an editor checks plugins the way
Bogey does; an existing one is left alone, so delete it and link again to regenerate:

```sh
cd monorepo && bogey plugins link ../extensions
```

A folder in `plugins/` is picked up the next time Bogey builds or its dev server restarts. Folders
that start with a dot (like `.parked/`) are skipped. `bogey plugins add` also writes into this
folder when linked this way, so install other people's plugins on an instance, not here.

## Releasing a plugin

1. Change the plugin's `version` in its `manifest.ts`.
2. Tag the commit `<plugin>-v<version>`, for example `lockdown-v1.0.0`, and push the tag.
3. The release workflow checks the tag against the manifest, attests
   `<plugin>-<version>.tar.gz`, and publishes it as a GitHub Release asset through a draft.
   Turn on *immutable releases* for this repository (Settings → General, or
   `gh api -X PUT repos/0xethen/bogeyx/immutable-releases`) and GitHub also signs a release
   attestation, which `bogey plugins add` checks with `gh`.
